# Contributing to Prompt2App

[English](#english) · [中文](#中文)

---

## English

Thanks for your interest in Prompt2App! All kinds of contributions are welcome: code, docs, app templates, bug reports and feature requests.

> The project is in early development. Structure, commands and APIs may change frequently — please open an issue to discuss larger changes before starting work.

### Reporting bugs

Open an [issue](https://github.com/prompt2app/prompt2app/issues) and include:

- What you did (the prompt you used, if relevant) and what you expected
- What actually happened, with logs or screenshots
- Your environment: OS, Docker version, LLM provider and model

### Suggesting features

Open an issue describing the problem you want to solve and the business scenario behind it. Real-world use cases help us prioritize.

### Submitting a pull request

1. Fork the repository and create a branch from `main` (e.g. `feat/approval-engine`, `fix/login-redirect`).
2. Keep each PR focused on one change. Large changes should be discussed in an issue first.
3. Add or update tests and docs where applicable.
4. Make sure the project builds and tests pass locally.
5. Write clear commit messages. We recommend [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `refactor:`, ...).
6. Open the PR, describe what changed and why, and link related issues.

### Contributing app templates

Templates (e.g. a CRM or leave-approval app) are a great way to contribute. Include the prompt used to generate it, a short description of the scenario, and screenshots if possible.

## 中文

感谢你关注 Prompt2App！欢迎任何形式的贡献：代码、文档、应用模板、Bug 反馈和功能建议。

> 项目处于早期开发阶段，目录结构、命令和接口可能频繁调整。较大的改动请先开 Issue 讨论，再动手开发。

### 反馈 Bug

请提交 [Issue](https://github.com/prompt2app/prompt2app/issues)，并说明：

- 你做了什么（如相关，附上使用的那句需求描述）以及期望的结果
- 实际发生了什么，附上日志或截图
- 运行环境：操作系统、Docker 版本、大模型服务商及模型

### 功能建议

提交 Issue，描述你想解决的问题及背后的业务场景。真实的使用场景能帮助我们排定优先级。

### 提交 Pull Request

1. Fork 本仓库，并基于 `main` 创建分支（如 `feat/approval-engine`、`fix/login-redirect`）。
2. 每个 PR 只做一件事。较大的改动请先在 Issue 中讨论。
3. 如适用，请补充或更新测试与文档。
4. 确保本地构建和测试通过。
5. 提交信息清晰明了，推荐使用 [Conventional Commits](https://www.conventionalcommits.org/zh-hans/) 规范（`feat:`、`fix:`、`docs:`、`refactor:` 等）。
6. 提交 PR，说明改了什么、为什么改，并关联相关 Issue。

### 贡献应用模板

应用模板（如 CRM、请假审批）是很好的贡献方式。请附上生成它所用的需求描述、场景简介，最好再附几张截图。

### 开源协议

提交贡献即表示你同意你的贡献以 [Apache License 2.0](./LICENSE) 协议授权。
